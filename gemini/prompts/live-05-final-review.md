# Phase 5 — review the report after repairs

Read `skills/pbir-reading.md`, `skills/data-honesty.md`, `skills/visual-qa.md`, `work/inventory.json`, `work/report-digest.json`, `work/live-interpretation.json`, `work/live-build.json`, `output/dynamic/index.html`, and `output/dynamic/backend.mjs`, plus `work/fix-request.json` if present. Check originals under `input/` where the digest is not enough. Do not read `.env` or run shell commands. Do not edit generated report files.

This is an independent skeptical review after page repairs or automatic fixes. The runner has already executed the backend: `work/live-selfcheck.json` lists every data visual's row count, a sample of the actual values, and suspicious results; use them. Check that the HTML sends `filters` in exactly the shape the backend reads (`filtersContract`) and that `prompts/backend-contract.md` is followed. Check every selected page and visual listed in `work/inventory.json` against its definition, the source connector path, transformations, measures, relationships, filter context, layout, and credential isolation. Do not require pages absent from the inventory. Do not count ID markers or generic chart cards as implemented visuals. Use `blocked` only for concrete, fixable defects (fabricated or missing visuals, missing required sources/calculations, unsafe code, broken interactions) and state the exact fix. Exact numerical/visual parity cannot be certified without comparison to Power BI; that is a warning.

Write `work/live-final-review.json` with `status` (exactly one of `pass`, `warnings`, `blocked`), `findings` (array of objects with `severity`, `file`, `description`, `fix`), `limitations` (array), `unverified` (array), `pageCoverage`, `visualCoverage`, and `sourceCoverage`.
