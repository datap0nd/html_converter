# Phase 2 — build the live HTML report and source-specific local backend

Read `work/live-interpretation.json`, `work/report-digest.json`, `work/inventory.json`, `skills/data-honesty.md`, and `skills/visual-qa.md`. Open original PBIP files only for details the digest lacks. Do not read `.env` or run shell commands. Build from the report's *actual* sources; do not substitute PostgreSQL for other connectors. Keep credentials server-side. Do not use Fabric, Power BI Service, CDNs, telemetry, or remote assets. Edit only `output/dynamic/` and `work/live-build.json`.

## Backend contract (`output/dynamic/backend.mjs`)

Export `async function createBackend({ env, root, inputDir, helpers })` returning `{ healthcheck, query }`.

- `env` holds the values from the user's private `.env` (for example `PG_HOST`, `PG_USER`, `PG_PASSWORD`, `PG_SSL_MODE`, `PG_SSL_CA_FILE`, `PG_ALLOW_NATIVE_QUERIES`). Read settings only from `env`, never from `process.env` or files.
- Do NOT import the converter's scripts with relative paths such as `../../scripts/sources.mjs`: the file is moved after this phase and such paths break. Use `helpers` instead: `helpers.sources` (exports `listLiveSources`, `fetchLivePage`, `postgresNativeQuery`, `postgresQuery`, `loadAllData`, `testPostgresConnection`), `helpers.core` (exports `parseCsv`, `readJson`, `findPostgresSources`, `findDirectCsvSources`), and `await helpers.loadPg()` which returns the installed `pg` module (use `new (await helpers.loadPg()).Pool(...)` or `.Client`).
- Only Node built-ins and `helpers` are available. Do not import any other npm package (no `mssql`, `csv-parse`, `xlsx`, ...). If a connector needs a driver that is not available, `healthcheck()` must report it as a blocking issue.
- `healthcheck()` connects to every required source and returns `{ok:true, sources:[...]}` only if all work; otherwise `{ok:false, issues:[...]}` with one plain-language string per problem (missing credential names, unreachable host, unreadable file path). Never include secret values.
- `query({visualId, filters, limit})` recomputes that visual from live sources with its Power Query steps, relationships, DAX-like calculations, and filter context translated as accurately as the evidence permits. Return `{rows:[...], columns:[...], placeholder:boolean, limitations:[...]}`. Use parameterized SQL, read-only transactions, bounded queries (`limit`), and statement timeouts (at most 60 seconds). Throw an Error with a clear message for an unknown `visualId`. For unsupported semantics return `placeholder:true` with a precise explanation; never fabricate values. Decorative visuals need no query.
- `filters` is the object your HTML sends as JSON. Define its shape once (for example `{ "<Table>.<Column>": ["value", ...] }` or `{ "<Table>.<Column>": {"from": ..., "to": ...} }`), use exactly that shape in both files, and document it as `filtersContract` in `work/live-build.json`. An empty object means the report's default filter state.
- File paths come from the PBIP definitions (see the digest `sources`) or `env`, never guessed. Do not read or write any other local files and do not contact any host other than the report's data sources.

## HTML (`output/dynamic/index.html`)

Inline CSS and JavaScript only, no external assets. Call `/api/report?visual=<visual-id>&filters=<URL-encoded JSON>` for every data visual. Reconstruct every selected page and every visual with role `data` or `decorative` from `work/inventory.json`. The runner verifies coverage by searching the HTML source text, so write each page container with the literal attribute `data-page-id="<exact page id>"` and each visual element with the literal attribute `data-visual-id="<exact visual id>"` directly in the markup; do not create these attributes only from JavaScript. Do not add pages absent from the inventory. Recreate slicer/filter controls and make them drive the backend. Use proper chart/table rendering with the PBIR titles, positions, and number formats; unsupported visuals must be explicitly labeled, never generic fake charts. Include a visible `id="report-status"` element saying this is an AI reconstruction requiring comparison with Power BI, listing unsupported or unverified behavior. Show a visible error inside a visual if its request fails. No raw source-data explorer.

Write `work/live-build.json` with `implemented`, `placeholders`, `limitations`, `sourcePaths`, `credentialsNeeded`, and `filtersContract`. Do not claim a completed faithful conversion if any required visual or calculation is missing. Write all three files with the file-writing tool.
