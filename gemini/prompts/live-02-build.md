# Phase 2 — build the live HTML report and source-specific local backend

Read `prompts/backend-contract.md` first: it is the exact contract the runner executes and enforces. Then read `work/live-interpretation.json`, `work/report-digest.json`, `work/inventory.json`, `skills/data-honesty.md`, and `skills/visual-qa.md`. Open original PBIP files only for details the digest lacks. Do not read `.env` or run shell commands. Build from the report's *actual* sources; do not substitute PostgreSQL for other connectors. Keep credentials server-side. Do not use Fabric, Power BI Service, CDNs, telemetry, or remote assets. Edit only `output/dynamic/` and `work/live-build.json`.

Write `output/dynamic/backend.mjs` following the contract. `query()` recomputes each data visual from live sources with its Power Query transformations, model relationships, DAX-like calculations, and filter context translated as accurately as the PBIP evidence permits. File paths come from the digest (`sources.files`, already resolved through M parameters, with `csvOptions`) or `env`, never guessed. "Enter Data" tables are in `helpers.enterData`. If a connector requires a driver that is not available, report it as a blocking issue in `healthcheck()`; do not pretend it works.

Write `output/dynamic/index.html` following the contract. Reconstruct every selected page and every visual with role `data` or `decorative`. Recreate slicer/filter controls and make them drive the backend through the documented `filters` object. Use proper chart/table rendering with the PBIR titles, positions, and number formats; unsupported visuals must be explicitly labeled, never generic fake charts. No raw source-data explorer.

Write `work/live-build.json` with `implemented`, `placeholders`, `limitations`, `sourcePaths`, `credentialsNeeded`, and `filtersContract`. Do not claim a completed faithful conversion if any required visual or calculation is missing. Large files may be written in parts: create the file with `write_file`, then extend it with `replace`.
